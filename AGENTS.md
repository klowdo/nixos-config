# Repository instructions

## Commit changes

- Commit the changes you make in this repository before finishing a task. Do not leave your own work uncommitted.
- Use semantic (Conventional Commits) messages in the form `type(scope): short imperative summary` (for example, `feat(darwin): install Visual Studio Code`).
- Check `git status` before and after the commit, and report the commit hash in your final response.
- Stage only files or hunks relevant to your task. Do not include unrelated pre-existing staged or unstaged changes in your commit; ask before committing someone else's pending work.
- Do not push commits unless explicitly requested.
